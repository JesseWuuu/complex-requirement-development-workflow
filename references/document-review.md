# 阶段 6：文档独立审阅与返修

三份文档分别批准后、处理审阅发现或从实施阶段返回文档修订时读取。本文统一定义文档返修分类、授权与重新确认；审阅者派发和恢复见[委派参考](subagent-delegation.md)，字段记录见[跨对话续接](cross-conversation-resumption.md)。

## 独立审阅

审阅前核对 PRD、适用规则和关键依据，更新技术依据与规划指纹；相关漂移先返回最早受影响阶段。派发未参与文档主笔或关键技术结论形成的干净 Sub Agent，只读检查三份文档与判断结论所需的最小原始需求和仓库证据。不得提供预期结论或拟议修复；不能以主 Agent 自审替代。

审阅覆盖：

- 必要性：产品规则有来源，测试符合[场景准入](test-writing.md#场景准入)，新增目标按[技术依据中的分级评估](technical-grounding.md#最小修改与复用优先)判断，没有为形式完整而扩大范围。
- 一致性：产品语义归 Spec，下游不重复定义或擅自扩展；关键覆盖由既有保证或具体实施步骤承接。
- 依据与可执行性：重要目标、命令、依赖和验证方式有当前证据；共享边界、真实入口和关键回归无缺口。
- 可读性与时效性：无重复清单、过程历史、无用章节或使方案失效的后续决定。

审阅者只返回带证据、影响与严重度的发现，不编辑文件或批准文档。主 Agent 核实发现后按下方分类处置。

## 返修分级

### 明确的编辑性修正

仅修正错别字、排版、等义表述或恢复已确定引用目标的失效链接，不改变产品语义、范围、测试覆盖、实施目标、依赖、验证义务或风险。更换技术目标、删减场景、改变命令或消除尚未裁决的方案歧义不属于编辑性修正。

在用户已授权的文档范围内，主 Agent 可直接完成这类修正并展示差异与理由，无需另请返修授权或文档重批。用户明确禁止改动或只授权特定文档时遵守该限制；不清楚影响时先核对，无法证明等义则按实质返修处理。

修正后记录等义依据并更新文件摘要和规划指纹，保留原文档批准记录；旧独立审阅对新内容失效，必须按当前内容复审，不能仅改结论绑定。已有产品代码授权不随新规划自动迁移。该例外不适用于阶段 7 终结审阅之后的自动修复。

### 实质返修

改变产品规则、覆盖义务、实施方案或上述边界的修订，先以 `<需求代号> · 阶段 6/7 · 独立审阅返修 · 待决定`（工作区附模块代号）呈现发现、证据与严重度、最早返回阶段、受影响文档和建议方向。

已有明确授权覆盖此次修订时直接执行；否则保持受影响文档不变，等待用户明确同意返回阶段、文档与方向。未决返修、拒绝阻塞性修订或未明确的替代方向均不能新取得阶段 6 通过结论或实施授权。阶段 7 实施中局部待决时，仅按[实施规则](code-execution.md#实施中的变更分级)延续不受影响的有效原授权，检查点条件见[审阅与实施记录](cross-conversation-resumption.md#审阅与实施记录)。原文档批准本身不授权实质返修。

授权后按最早受影响阶段修订，并重新取得所属文档批准，再更新依赖文档。同一项已确认技术修正仅影响 Test 与 Implementation、Spec 不变时，可按该顺序更新两份已授权目标，请求一次明确命名两份文档的联合批准。联合批准不授权产品代码实施。

## 返回阶段与复审

方向失效返回阶段 1；新产品决策或未经晋升的行为返回阶段 2；产品规则表达错误返回阶段 3；测试覆盖或准入错误返回阶段 4；实施目标、owner、共享机制或必要性错误返回阶段 5。按错误来源定位最早阶段，只补齐相关依据，不以连续补丁替代基础问题的核对。

任何文档内容变化都使旧审阅失效；实质变化还使受影响文档批准及代码授权失效。修订后的审阅结论必须绑定当前规划，按委派参考复用原 reviewer 做聚焦复审，或使用新的干净 reviewer 重新审阅。

当前输入的独立审阅无阻塞发现、所需修订已完成且重开的文档均获批准时，主 Agent 才将阶段 6 记为通过。报告三份文档路径、实际发现及处理结果，并请求单独的产品代码实施授权。状态与指纹记录只证明当前绑定，不能替代用户决定。
