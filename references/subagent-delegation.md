# Sub Agent 派发与回收

本参考文件定义任务包、并发限制、审阅者独立性与重试。文档返修见[文档独立审阅](document-review.md)，实施变更与完成边界见[实施规则](code-execution.md)。任务包只服务当前运行过程，跨对话只保存有效结论。

## 收益门槛与数量

- 阶段 2、4、5、6 的调查以及阶段 8 的实施，只有可并行的独立技术面能明显节省时间时才派发；文档主笔、共享接缝、重叠写入和局部小修由主 Agent 完成。
- 阶段 2、4、5、6 同一时刻最多 2 个调查任务；阶段 8 同一时刻最多 2 个实施任务。不要为了用满并发而切分。
- 阶段 7 只允许一个当前 reviewer，独立审阅不适用收益判断；任务要求见“阶段 7 独立审阅”。其余任务的失败处理见“执行边界与停止条件”。

## 按阶段切分

- **阶段 2：** 可拆分 Figma/设计事实、入口与导航、API/数据/状态、实验等互不依赖的只读证据面。主 Agent 负责端到端语义和冲突裁决。
- **阶段 4：** 只派发现有逻辑风险或契约覆盖调查；`test.md` 由主 Agent 统一编写。
- **阶段 5：** 只派发会影响核心路径或取舍的独立调查；`technical-design.md` 由主 Agent 提炼，不委派多份并列方案。
- **阶段 6：** 只派发实施目标、文件归属、新机制必要性或验证目标调查；`implementation.md` 由主 Agent 统一编写。
- **阶段 7：** 按下方独立审阅规则派发。
- **阶段 8 实施：** 只从当前获准批次生成互不重叠的写入任务；主 Agent 可按[实施变更分级](code-execution.md#实施中的变更分级)补充运行时目标。共享模型、公共接缝和最终集成保留给主 Agent。

## 运行时任务包

每个任务包包含：

1. 当前阶段和单一、有边界的目标；
2. 准确的需求、文档、仓库根目录和适用规则；
3. 允许读取的范围；写入任务还要给出唯一写入范围和禁止目标；
4. 依赖、共享接缝与主 Agent 负责的集成点；
5. 精简返回格式：结论、证据、阻塞、受影响路径、验证和偏差。

实际 Agent ID、等待记录、修订次数和任务包清单只保留在当前对话上下文。只有结论会改变后续决策时，才把精简结论写入权威正式文档、`grounding-pack.md` 或对应审阅记录；不要创建独立派发账本。

阶段 8 只从当前获准批次派发依赖已满足且写入范围不重叠的实施包；批次交付与暂停按[实施规则](code-execution.md#批次执行)，等待用户时不得留有运行中的写入任务。Sub Agent 发现需要补充目标时，返回路径、必要性与影响，由主 Agent 按[实施变更分级](code-execution.md#实施中的变更分级)裁决、接管或更新任务范围。工具不可用或收益下降时，主 Agent 可按原顺序接管。

## 审阅恢复

阶段 7 独立文档审阅复用绑定当前输入的完整结论。当前 reviewer 失败、不可继续或没有完整结论时，对相同输入最多再执行一次完整审阅；第二次仍无完整结论则阻塞，不能由主 Agent 自审替代。输入变化时旧结论失效，按[文档返修规则](document-review.md)处理相关修订和批准后，对新输入重新计数。检查点只保存当前 reviewer 与 `attempt`，不保存替代关系。

## 阶段 7 独立审阅

使用未参与文档主笔或关键技术结论的干净 Sub Agent，按[文档独立审阅](document-review.md#独立审阅)检查四份正式文档；只提供原始 PRD、当前技术依据和判断所需的最小仓库证据，不提供主 Agent 的预期结论、猜测或拟议修复。

返回先列有证据的阻塞发现，没有发现时明确审阅边界和无发现结论。审阅者不得编辑文件、定义新产品语义或批准确认节点。

主 Agent 核实发现并按[文档返修分级](document-review.md#返修分级)处理。内容修订后，原 reviewer 仍可调用时对本轮改动及其影响做聚焦复审；否则用新的干净 reviewer 对当前完整输入重新审阅。新输入重新计数，同一输入的失败重试仍按“审阅恢复”限制。

跨对话结论记入 `consistency_review`，绑定当前规划指纹。

## 执行边界与停止条件

- Sub Agent 不得新增产品语义、自行扩大运行时授权范围、改变已批准规则或跨越确认节点。
- 只读任务不得编辑文件；写入任务只能修改明确授权目标。
- 新发现会改变上游规则、外部契约、依赖、实质风险或目标归属时，停止相关写入并返回主 Agent，不自行回退整个需求。
- 发现写入范围重叠时停止后启动或越界的任务，由主 Agent 检查已产生改动。
- 两个调查结论冲突时由主 Agent 根据权威来源裁决，不增加第三个 Agent 投票。
- 调查或实施结果可向原 Agent 发送一次聚焦补全；仍错误、缺证据或越界时由主 Agent 收窄范围并接管，不反复换 Agent。阶段 7 按“审阅恢复”处理，不能由主 Agent 自审通过。
- 协调和复核成本已经不低于预计节省时间时，停止继续派发并串行完成。

## 结果回收

主 Agent 只吸收精简结论，不复制原始跟踪信息、长日志或完整工具输出。对关键事实、写入范围和验证结果做必要复核；解决冲突后再处理共享接缝与整合。实施偏差按[实施规则](code-execution.md)分级处理；改变上游规则或批准边界的实质变化返回对应确认节点，不静默合并。
