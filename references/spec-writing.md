# Spec 写作指南

本参考文件扩展父级 `SKILL.md` 的核心文档规则，不替代或覆盖这些规则。仅在编写或实质修订 `spec.md` 前读取。

## 核心审阅问题

要求的产品行为是否正确、完整且边界明确？

## 内容边界

Spec 正文负责产品语义。只包含：

- 问题、期望结果、范围、边界和重要的非目标；
- 关键规则、不变量、领域状态、状态转换和外部可观察行为；
- 会影响产品行为的逻辑数据或外部契约；
- 已确认决策、范围明确的非阻塞假设，以及决定受影响 UI 的 Figma 事实。

正文排除未解决阻塞项、实施步骤、实施约束、仓库清单、无关日期、框架或分层选择、模块、文件、类、函数和技术方案。阻塞项应先返回阶段 2 解决。返修时另按主 Skill 的[文档修订记录](../SKILL.md#文档修订记录)保留修订日期与改动摘要。

## 契约准入

产品规则统一按主 Skill 的“契约晋升门槛”纳入，本指南不另定义来源或例外。存在尚未解决的产品选择时，返回阶段 2 解决，不在 Spec 中替用户作决定。

## 追溯

仅对下游文档必须引用的关键规则使用 `R-*`。从属条件应保留在同一规则下。只有结论关键、存在争议或不明显时才添加来源指针。

交付前逐条尝试删除：删除后仍能完整表达原始需求、已确认决策和必须保留的既有外部行为时，该规则不应保留。
