# Spec 写作指南

本参考文件扩展父级 `SKILL.md` 的核心文档规则，不替代或覆盖这些规则。仅在编写或实质修订 `spec.md` 前读取。

## 核心审阅问题

要求的产品行为是否正确、完整且边界明确？

## 内容边界

Spec 负责产品语义。只包含：

- 问题、期望结果、范围、边界和重要的非目标；
- 关键规则、不变量、领域状态、状态转换和外部可观察行为；
- 会影响产品行为的逻辑数据或外部契约；
- 已确认决策、范围明确的非阻塞假设，以及决定受影响 UI 的 Figma 事实。

排除未解决阻塞项、实施步骤、实施约束、仓库清单、日期、框架或分层选择、模块、文件、类、函数和技术方案。阻塞项应先返回阶段 2 解决；代码证据只有在证明必须保留的既有外部行为或唯一不可避免结果时，才能转化为产品规则。

## 契约准入

每条规则必须能追溯到 PRD、用户已确认决策、Figma 明示事实，或本次变更必须保留的既有外部行为。仓库当前实现可以证明行为和约束，但不能单独定义新的期望行为。

非上游明示的可观察结果只有在它是需求成立时唯一且不可避免的结果时才能进入 Spec；若两种不同外部结果都能满足目标，则返回阶段 2 作为产品选择。并发、缓存、线程、生命周期、账户隔离等技术风险默认不写成产品规则。

## 追溯

仅对下游文档必须引用的关键规则使用 `R-*`。从属条件应保留在同一规则下。只有结论关键、存在争议或不明显时才添加来源指针。

交付前逐条尝试删除：删除后仍能完整表达原始需求、已确认决策和必须保留的既有外部行为时，该规则不应保留。
